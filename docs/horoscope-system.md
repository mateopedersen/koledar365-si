# Slovenian horoscope system

## Content and dates

The 12 sign profiles and daily interpretation bank are original Slovenian editorial text. They are entertainment, not scientifically established predictions. No publisher's horoscope is scraped, translated, or passed off as original. Actual geocentric Sun/Moon positions select the symbolic themes. The reference instant is explicitly local noon in Europe/Ljubljana.

`lib/horoscope/edition.mjs` calculates an edition for a civil date. The production Pages Function `/horoskop/dnevno.json` computes today's edition on demand, using the Ljubljana date, and returns `Cache-Control: no-store`. Its in-memory cache is keyed by date. Yesterday and the preceding seven days are available; future requests are rejected. Browser refreshes never relabel an older edition as today.

`node script/generate_daily_horoscope.mjs` writes the same original edition into the public JSON and editorial snapshot. Repeated runs on the same date are idempotent. The Pages publication workflow regenerates the snapshot daily at 22:15 and 23:15 UTC, covering local midnight in summer and winter. The separate Daily Slovenian horoscopes workflow checks the endpoint and all 13 public pages at 03:17, 04:17 and 07:47 UTC. It waits for an active publisher or starts one recovery build, then verifies publication. GitHub schedules can be delayed; request-time generation does not depend on them. Infrastructure outages can still prevent access and should be investigated from failed workflow logs.

## Ascendant and privacy

The calculator is local to the browser. Birth fields have no form names, start disabled until the handler is installed, are never stored, and are not included in a network request. It lazy-loads a 28.5 kB astronomy bundle only when calculation is requested. Timezone conversion uses the browser's historical IANA timezone data, detects nonexistent times, and asks users to distinguish repeated times. Unknown birth time must not be guessed.

The tropical ascendant is the eastern intersection of the ecliptic and local horizon, using true sidereal time and obliquity. Borderline results explain sensitivity to birth time. City coordinates are city centers, with manual coordinates/timezone available. Results are limited to birth dates from 1900 through today; historical timezone accuracy also depends on the user's browser data.

Astronomy Engine 2.1.19 is vendored under MIT with its license. `evidence/horoscope-ascendant-reference.json` contains 48 synthetic Swiss Ephemeris reference cases, with no real person's birth details. The exact solar-season intervals for 2026–2030 are generated by `script/build_horoscope_seasons.mjs`; outside those years the UI retains clearly approximate conventional date ranges.

## Verification and maintenance

- `node script/test_horoscope.mjs`: date rollover, DST gaps/folds, reference ascendants, all sign editions and Function response contracts.
- `bundle exec rails test test/integration/horoscope_test.rb`: all 14 horoscope routes, canonical headings, calculator privacy defaults, real edition dates and navigation.
- `node script/verify_horoscope_live.mjs`: production endpoint plus hub and all 12 sign pages must have today's actual date.
- Full publication: daily generation, `bundle exec ruby script/rebuild_free.rb`, then existing static, catalogue and vector identity checks.

When changing browser scripts or SVG bytes, increment their versioned filenames and references. CSS uses the existing content-hashed publication pipeline. Review the original language bank when extending variety; changing a date alone is never a new daily edition.
